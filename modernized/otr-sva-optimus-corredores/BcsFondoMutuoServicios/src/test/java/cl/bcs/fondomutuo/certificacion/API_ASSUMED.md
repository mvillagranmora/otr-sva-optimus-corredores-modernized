# API assumed by the FMM-CER tests (F3 W3, tanda T1: fronts F-A and F-B of `CertificarSolicitudAporteRescate`)

The production code does NOT exist yet (red before code). The tests of this package (`CasoCer`, `SujetoCer`, `ParadaT1`, `CerCostura`, `CerEquivalenciaTest`, `CerDeterminismoTest`,
`CerReglasTest`, `CerCompuertaTest`, plus the generated `CerTablasLiterales`) are written against EXACTLY the classes, constructors and methods below, all in package
`cl.bcs.fondomutuo.certificacion` (main source set) unless another package is named. Legacy FQN: `cl.bcs.fondomutuo.CertificarSolicitudAporteRescate` (3.052 lines, `logica` CCN 95).
Cards FM-CER-01..20 and 23 and defects D-F3B-01/08/12/16/31, D-NOR-9/16 of `RULES_FONDOMUTUO_F3_B.md`. Decisions of the plan applied: (1) migration by FRONTS in the order of section 12 of
the rules (T1 = F-A + F-B); the final class is ONE facade that keeps the order of the phases of section 7; (2) replicate bug for bug; (3) collaborators that are not ported stay behind PORTS
(for T1 only the two Plataforma reads `EntregarPreciosTasas` and `CalcularParidad`, that already have ports); (4) company without configuration: the kit's `ParametroNoEncontradoException`
is kept (DESVIO-KIT-1, only the slugs `empresa-sin-configuracion`, `empresa-inexistente`, `contrato-empresa-nula`); (5) package `cl.bcs.fondomutuo.certificacion`, prefix
`CertificarAporteRescate`, NO JavaCall handler, NO allow-list entry, NO list, NO gate flag until T5.

## 0. THE SEAM ("costura") of T1 and what it pins

F-B has no output of its own: its amounts, its partition, its indicators and its date are only seen in what comes AFTER (collaborator calls, writes). T1 therefore defines a seam:

```
logica(entrada) = F-A (header, requirements, parameters, reads, quota value, 8 rules, early exit)        <- REAL in T1
                  F-B (indicators, recalculation with the real CalcularMontoNumeroCuota, effective date,
                       partition and order, GEN_OCSNEG)                                                    <- REAL in T1
                  return posteriores.continuar(contexto)                                                   <- the SEAM: port CertificarAporteRescateFasesPosteriores
                  (aportes, rescates, UPDATE, notifications, switch, log of the system, final log = fronts C..J, T2..T5)
```

In the tests the port is a double that RECORDS the `CertificarAporteRescateContexto` it receives and throws `ParadaT1` (`"PARADA_T1"`); the facade must let it go up untouched (the legacy `logica`
has no `try/catch`). Two kinds of case, written by `cases_cer_caso.py` in the `ref` of `case.json`:

| Kind | Legacy outcome | What the golden holds | What the test compares |
|---|---|---|---|
| TERMINAL (no tag) | ends or throws INSIDE F-A / F-B: requirements error, empty list, duplicates, nothing found, parameter missing, `NullPointerException` / `IllegalStateException` / `ArithmeticException` of a read or of the calculation, NO solicitud passes the 8 rules (early exit FM-CER-14: log + counter 1), `ParadaT1` must NOT appear | the whole oracle dump | the WHOLE dump, section by section (output text, exception class, CallServlet decision, tables before / right after the call / after the decision, collaborator calls, sequences, previous requests, session) |
| `T1-costura:parada` | continues past F-B | the legacy run STOPPED at the first collaborator that F-C / F-D / F-J reach (`SaldoFlujoCaja`, `CalculaCustodiaRescate`, `ProcesarCustodiaFondoMutuo`, `NotificarEstadoOrdenFondoMutuo` scripted to fail with `PARADA_T1`): `excepcion = Exception: PARADA_T1`, `ROLLBACK_HTTP500`, the collaborator calls up to the stop with their full arguments, the tables BEFORE any write | the T1 prefix of the collaborator calls (the calls of F-A / F-B: `EntregarPreciosTasas`, `CalcularParidad`), the tables unchanged, no sequence consumed, and the context agrees with the ARGUMENTS of the stop collaborator (pairs and date of `SaldoFlujoCaja`, rescates of `CalculaCustodiaRescate`) and with WHICH collaborator it is (partition, indicators, states) |
| `T1-costura:completo` | continues past F-B | the whole legacy run with BENIGN collaborator doubles (`seed/doubles-cer.json` + the answers built by `cases_cer_caso.benignos`): full output, the UPDATE to CRT, every collaborator entry | the context agrees with: the state and code of every row of the output (F-A / F-B rejections, the balance rejection read through `OperaSaldoNegativo`), the order of the rows, the amounts written by the UPDATE after the FM-CER-23 format, the aportes sent to custody (ascending ids, formatted amounts), the rescates sent to `CalculaCustodiaRescate`, the ids notified |

The `completo` golden is also the base of T2..T5: those tanda compare the same cases as a whole once the later fronts exist. The two variants of a case share seed and input (`-parada` suffix).

What the golden of a continuing case does NOT pin in T1 (later fronts): `CostoUF`, `Spread` and `RentabilidadReal` of a RESCATE (F-D, FM-CER-41), the amounts of a total rescate (FM-CER-33), the cash-flow balance rule itself (F-C; it is only read to check `OperaSaldoNegativo`), anything written by custody, cuenta de inversion, Tesoreria, Facturacion, Spot, reinversion, switch, notifications and the final logs, `ParidadFechaCertificacion` (the H2 types the parameter of `COALESCE(:Paridad, 0)` as INTEGER and rounds it: engine limit, HANA keeps the decimals) and the 11-amount format of `MontoLiquido*` / `MontoRetencion*` (not written by the UPDATE nor sent by any first collaborator; `CerReglasTest` pins the pure rule with literals).

## 4. Behaviour the tests pin (bug for bug; the golden is the oracle, this is the index)

Order of the facade (the order decides WHICH exception or code wins):

1. `PLATAFORMA/PLA.PaisSistema` (`ConfiguracionSistemaPort.entero`: missing = `Exception("Parametro ... no encontrado")`, not numeric = `NumberFormatException`) -> `RevisarRequisitosBasicos` (counter = `ConteoErrores`, > 0 returns counter 1 with the messages of the platform) -> `p_Solicitudes.size() == 0` (`NO_SE_INGRESARON_SOLICITUDES`, id 0) -> repeated ids with `ArrayList.contains` (two nulls are a duplicate; `SOLICITUD_DUPLICADA`) -> the mandatory parameters in this order: `PLA.FechaSistema`, `TipoComprobanteFacturaNoApv`, `TipoComprobanteFacturaApv`, `CALCULAR_COMISION_CERTIFICACION`, `VALIDAR_CERTIFICACION`, `RESCATE_GENERA_VENTA_SPOT_DOLAR`, `RESCATE_COMISION_COMPROBANTE_AUTOMATICO`, then `APV.PorcentajeRetencion` (optional, 0), `PLA.NotificarEstadoOrdenOWP` (mandatory).
2. Reads, in this order and nothing else: the solicitudes by DISTINCT ids and company; ids for the traspaso queries = ids + the related ids <> 0 (not distinct); `SelectEstados`; the vouchers; the APV traspasos (`Collectors.toMap`: a repeated id is `IllegalStateException`); the not APV ones; the TGR person and the SII person (document parameter absent = `""`, still queried); `putAll`; `Hashes.aHash(estados)` (BEFORE the check of an empty read, D-NOR-9); an empty read = counter 1 + `UI_NO_EXISTEN_SOLICITUDES_CUMPLAN_FILTROS` (no log).
3. The quota value of EVERY solicitud read: one `PreciosTasasPort.entregar` call with `PreciosTasasContrato.Entrada` {`p_IdEmpresa`, `p_IdUsuario`, `p_IdModulo`, `p_IdPais = paisSistema`, one `DatosInstrumentos` per solicitud: `FechaConsulta = yyyy-MM-dd 00:00:00.000` of `FechaValorCuota`, `IdClasificacionTipoInstrumento "FM"`, `IdInstrumento`, `IdMoneda = IdMonedaFondo`, `IdRegistro = IdSolicitudAporteRescate`, `IdTipoCriterioTasa "0"`, `IdTipoInstrumento`, `IdUso "CARTERA"`, `Nemotecnico = IdSerieFondo`, `PlazoResidual 0`, `TipoCartera "0"`}; the answer is keyed by `IdRegistro` dropping rows without `IdInstrumento` (`Collectors.toMap`: a repeated key is `IllegalStateException`).
4. The eight rules per solicitud, `continue` at the first that fails (FM-CER-06..13, codes in `CerReglasTest`); `solicitudesPorProcesar == 0` = early exit FM-CER-14: counter 1, `P_OUT_RESULTADO` = `procesarSalida` of ALL the solicitudes, the log (`insertarLog`: one batch, ids `secuencias.siguientes("BSCL.FondoMutuo.BD.Secuencias::LogCertificacionAporteRescate", n)`, `n` = rows; `ValorCuota` / `NumeroCuotas` null as 0, `Simulacion = p_SimularOperacion`), return. `procesarSalida` throws `NullPointerException` when a state is not in `PLA.Estado` and writes `IdSolicitudAporteRescate = 0` when `p_CertificacionAporteSwitchSimulado = "S"`.
5. F-B: the indicators of the portfolios of the PEN / ADV (distinct) -> `Hashes.aHash` -> the recalculation (`CalcularMontoNumeroCuota` with one `Serie` per PEN / ADV solicitud: `IdInterno = IdSolicitudAporteRescate`, `Fecha = yyyy-MM-dd` of `FechaValorCuota`, `Monto = CostoMonedaLocal`, `NumeroCuotas`, `IdMonedaFondo`, `IdMonedaInversion = IdMoneda`, `TipoSolicitud`, `TipoFactorAjuste "UF"`, `IdEmpresa`, `IdTipoMovimientoFondoMutuo` ("" if null); not called without series) -> `Hashes.aHash(P_OUT_RESULTADO, IdInterno)` -> application (FM-CER-17) -> effective date -> partition -> `GEN_OCSNEG` for the portfolios of the aportes (queried even with no aportes: `IN (NULL)`; the FIRST row of the portfolio wins; absent = `"N"`) -> `posteriores.continuar(contexto)`.
6. Exceptions are NEVER caught by the facade except where the legacy does (the optional parameters). Nothing is written before the seam but the early-exit log.
