## 0. What the class is (read the card list first: RULES_FONDOMUTUO_F3_A.md 8.8)

`CargarValorCuota` validates a list of quota values and, ONLY when `p_SimularOperacion` is exactly `"N"`, writes `FMM.ValorCuotaHistorico` and `FMM.ValorCuota` and one
audit line (`AgregarLog`). It has **no commit and no rollback of its own**: the host (`CallServlet`, here `JavaCallUnitOfWorkFilter`) commits when the response counter
`P_OUT_ERRORESCONTADOR` is 0 and rolls back when it is greater than 0 (or absent, or on any exception). Consequence pinned by the goldens: a batch with ONE row with error has
already written its OK rows when the counter is computed and is rolled back as a whole (D-F3A-22). Decisions of the user (all of them are cases, none is corrected):
D-F3A-16..23 replicated bug for bug; **AgregarLog failure is swallowed** (decision 2, no DEV-F5 here); empty or unconfigured company: the kit's
`ParametroNoEncontradoException` is kept (decision 4, DESVIO-KIT-1, slug `empresa-sin-configuracion` only); own gate list `CARGAR_VALOR_CUOTA`, closed by default (decision 5).

## 2. Contract types (field names = legacy, JSON = legacy `Utils.getGsonBuilder()`)

* `Entrada`: `Long p_IdEmpresa; Long p_IdUsuario; Long p_IdPais = -1L; String p_IdModulo; String p_UsaReglasNegocio; String p_SimularOperacion; String p_AllFunds; List<ValorCuota> p_ValorCuota = new ArrayList<>()` (an absent key stays at the default; an explicit `null` list stays `null` and the legacy throws `NullPointerException` at `.size()`; a text `"1"` for a Long is coerced, `"abc"` raises `JsonSyntaxException`).
* `ValorCuota`: `String IDSERIEFONDO; String ISIN = ""; String IDMONEDA; String FECHACIERRE; BigDecimal VALORCUOTA; String OBSERVACION; String MENSAJEVALIDACION; String FECHACALCULO = ""; Long REGISTRO = 0L`. `VALORCUOTA` keeps the TEXT of the JSON number (`1500.50`, `1.5E+2`: Gson reads a `BigDecimal` from its text), which the output and the log show.
* `Resultado` (the 16 fields of the legacy `ResultadoCargaValorCuota`, IN THIS ORDER): `String IdSerieFondo; String IdMoneda; String ISIN; java.sql.Date FechaVigencia; BigDecimal ValorCuota = ZERO; BigDecimal ValorCuotaFechaAnterior = ZERO; String Observacion; Long DecimalesValorCuota; java.sql.Date FechaCalculo; String Estado; String DescEstado; Long IdEmpresa; String EmisorValorCuota = null; BigDecimal ParidadValorCuota = ONE; BigDecimal ValorCuotaCalculado = ZERO; BigDecimal VariacionValorCuota = ZERO`. `Estado` is `OK` / `ERR` / `ADV` (the legacy `ConstantesFondoMutuo`; `ADV` is unreachable, D-F3A-16).
* `Salida`: `Long P_OUT_ERRORESCONTADOR = 0L; List<Resultado> P_OUT_RESULTADO = []; List<kit.MensajeSalida> P_OUT_MENSAJES = []` IN THIS FIELD ORDER. Nulls ARE written (`serializeNulls`), a `java.sql.Date` is written as `yyyy-MM-dd HH:mm:ss.SSS` in the zone of the JVM when the Gson is CREATED (the goldens were recorded with the zone UTC and language en), `BigDecimal` with its `toString` (`100.00000000`, `5.000`, `0`).
* `SerieFondoIsin`: `String IdSerieFondo = ""; String ISIN = ""`. `ValorCuotaVigente`: `String IdSerieFondo; java.sql.Date FechaVigencia; BigDecimal ValorCuotaVigente = ZERO` with the legacy `hashCode` (`31 * IdSerieFondo.hashCode() + FechaVigencia.hashCode()`: a null serie is a `NullPointerException`) and `equals`.

## 3. How AgregarLog enters (decision 2) and how the ids of the historico are taken

* **Log.** Through the EXISTING `port.out.http.LogPort` (`JsonObject agregar(JsonObject entrada)`), with the JSON of `requisitos.contrato.LogContrato.InAgregarLog` built with `JsonLegacy.conNulos().toJsonTree(...)` (nulls written: `p_IdEmpresa`, `p_IdUsuario`, `p_IdModulo`, `p_UsaReglasNegocio`, `p_IdEstadoAutorizacion` are NOT filled by the legacy and go out as `null`; `p_IdTrabajo` 0). ONE call per request with one `Log` and one `DetalleLog` per row with `Estado != ERR`, in the order of the batch, after the four writes. **The call is skipped when no row is OK** (the real `AgregarLog` returns at once with an empty list: the oracle's double models that and records nothing). **ANY `Exception` raised by the port is swallowed** and the load goes on with the same output and the same commit decision (the legacy `catch (Exception) { printStackTrace }`, `AgregarLog.java:239-241`): `RuntimeException`, `ServicioNoServidoException` (the 503 of the router, NOT the DEV-F5 of Normal), `ColaboradorErrorException`, `NullPointerException` of an empty answer. A `java.lang.Error` is NOT swallowed (the legacy catches `Exception`). Difference to document for the owner (not testable here): the legacy `AgregarLog` wrote through the SAME connection (`AgregarLog.logica(con, ...)`), so a rollback of the batch by the host also removed the audit line; by HTTP the owner module commits on its own connection (`LogPort`), so after a batch rolled back for a row with error the audit line of its OK rows stays (as `LogPort` already documents, 5.4). The `ServicioNoServidoException` swallowed here must NOT set `EscrituraConfirmada` side effects that change the answer.
* **Ids.** The legacy takes the id INLINE from the sequence (`"BSCL.FondoMutuo.BD.Secuencias::ValorCuotaHistorico".NEXTVAL` in the INSERT, one value per row of the batch). The production asks the EXISTING `requisitos.SecuenciaPort` ONCE, `siguientes("BSCL.FondoMutuo.BD.Secuencias::ValorCuotaHistorico", n)` with `n` = number of rows to insert, **after step 1 and before step 2** (so a failing step 1 consumes no id; a failing step 2 has already consumed them), and binds `ids.get(i)` to the row i. With `n = 0` the port returns an empty list without touching the database (no request is recorded). The SQL FILE stays byte for byte the legacy one (`RecursosSqlTest` pins its SHA-256): the adapter replaces, in memory, the single token `"BSCL.FondoMutuo.BD.Secuencias::ValorCuotaHistorico".NEXTVAL` by the named parameter `:IdValorCuotaHistorico`. The oracle records the inline NEXTVAL as the same `{secuencia, cantidad}` entry of `secuenciasSolicitadas` (`ConexionCvc`), so both sides compare the same thing; ids are consecutive in the order of the rows.

## 4. Behaviour the tests pin (bug for bug; the golden is the oracle, this is the index)

* **Order of the whole request** (FM-CVC-02, 08): requisitos basicos (counter = number of errors, `ConteoErrores`) -> empty list (counter := 1, message `NO_SE_INGRESARON_VALORES_CUOTA` added to the requisitos messages) -> if the counter is > 0 return (nothing else is read) -> ISIN mode (`p_AllFunds` equalsIgnoreCase `"S"`: SELECT by ISIN, THEN `Collectors.toMap(IDSERIEFONDO)` which throws `IllegalStateException` for a repeated ISIN; ISIN without serie dropped without message; an ISIN in several series = one row per serie; none found = empty list, counter 0, nothing written) -> `obtenerResultado` -> writes only when `p_SimularOperacion` is exactly `"N"` -> messages and counter.
* **`obtenerResultado` reads and fails in this order** (the order decides WHICH exception wins; cases pin it): `PLATAFORMA/PLA.FechaSistema` (`ConfiguracionSistemaPort.texto`) -> duplicate map (`FechaLegacy.aFechaSql(FECHACIERRE)`: 10 or 19 characters, anything else `DateTimeParseException`, null `NullPointerException`; a null serie `NullPointerException` at the hash) -> series (`SeriesFondoPort`, `toMap`) -> existing values (`toMap` by `serie_fecha`: two stored values of the same serie and date = `IllegalStateException`, D-F3A-16) -> previous day (`ObtenerDiaAnterior` with `idPais = p_IdPais`, `diaHabil = "N"`, ONE reused `FechasIn` object whose `fechaInicial` ends as the `FECHACIERRE` of the LAST row, D-F3A-18; `toMap` by serie of the history rows with `EsUltimaCargaDiaria = 'S'`) -> per row: state, decimals, result (a null `VALORCUOTA` is a `NullPointerException` even for a row with error).
* **State of a row** (FM-CVC-04, first that applies): `MENSAJEVALIDACION` not `"OK"` (equals) -> `FORMATO_INVALIDO`; repeated (serie, date) in the request (ALL occurrences) -> `VALOR_CUOTA_DUPLICADO`; no serie -> `SERIE_NO_EXISTE`; value `compareTo(ZERO) == 0` -> `VALOR_CUOTA_INVALIDO` (negative passes); `"N".equals(p_AllFunds)` and `!IDMONEDA.equals(serie.IdMoneda)` -> `MONEDA_INCORRECTA` (D-F3A-20; a null `IDMONEDA` is a `NullPointerException`); `FECHACIERRE` after `PLA.FechaSistema` -> `FECHA_VALOR_CUOTA_INCORRECTA`; existing value in the date -> `ADV`/`VALOR_EXISTE_FECHA` (never: the map is keyed `serie_fecha` and read by serie); else `OK`.
* **Value that is written** (FM-CVC-05, D-F3A-17): the INPUT `VALORCUOTA` with all its scale (the `FLOOR` to the decimals of the serie is computed and discarded); `FechaVigencia` = the closing date (`0001-01-01` for `ERR`); `FechaCalculo` = system date, or in ISIN mode `FECHACALCULO` of the row (`0001-01-01` for `ERR`; empty/null/malformed raises); `EmisorValorCuota` = `IdEmisor` of the serie (`""` for `ERR`); `ParidadValorCuota` = 1; variation = `|((valor * 1 - anterior) / anterior [scale 3, HALF_EVEN]) * 100|` only when value and previous are not 0.
* **Writes** (FM-CVC-08..10, 14): in this order, the rows with `Estado != ERR`: (1) update `EsUltimaCargaDiaria = 'N'` for serie + date + company with `'S'`; (2) insert the historico (id from the port, `EsUltimaCargaDiaria = 'S'`, `FechaCarga = FechaCalculo`, `IdMoneda` = the one of the INPUT); (3) delete from `FMM.ValorCuota` by serie (no company filter; with the one-column PK it touches at most the row of that serie) the rows of the series chosen in (4); (4) insert ONE row per serie: the one with the most recent `FechaVigencia` of the batch (stable sort descending, `groupingBy` on a `HashMap`; no comparison with the stored value: D-F3A-19). Then (5) the log. The class never commits or rolls back.
* **Messages and counter** (FM-CVC-12): one `MensajeSalida.conTexto(0L, ERROR, DescEstado, {}, diccionario, resultado.IdEmpresa)` per `ERR` row; counter = `ConteoErrores.errores(messages)`; the OK and ADV rows give no message.
* **Exceptions**: class compared (the message only for a plain `Exception`: the missing parameters). KNOWN KIT DEVIATION **DESVIO-KIT-1**: for the slug `empresa-sin-configuracion` (a company with NO configuration rows) the legacy raises `NullPointerException` and the kit `ParametroNoEncontradoException` (`Exception: Parametro PLA.FechaSistema en modulo PLATAFORMA no encontrado`); the harness accepts either for that slug ONLY (`CasoCvc.DESVIO_KIT_EMPRESA_SIN_CONFIGURACION`). A company that has configuration rows but no `PLA.FechaSistema` is the plain `Exception` of the legacy in both.
* A failing write ends the request with the exception (HTTP 500, rollback by the host); what the earlier steps wrote stays in the session until that rollback (`tablasTrasLaLlamada`); the log port is not called and the `JdbcSQLException` text is not compared (class `SQLException`).
