# API assumed by the FMM-CPF tests (ConsultarCustodiaPortafolioFondoMutuo, F3 W1 front 8)

The production code does NOT exist yet. The tests of this package (`CasoCpf`, `SujetoCpf`, `CpfEquivalenciaTest`, `CpfDeterminismoTest`, `CpfReglasTest`,
`CpfCompuertaTest`) are written against EXACTLY the classes, constructors and methods below, all in package `cl.bcs.fondomutuo.consultas.custodia` (main source set) unless another
package is named. Legacy FQN: `cl.bcs.fondomutuo.ConsultarCustodiaPortafolioFondoMutuo` (the handler answers to it; registry id 3041, 8.886 uses, plan F3 section 10: the Java class is the
live implementation). Design = F1/F2/FSA/DET style: service + read ports + JavaCall handler, closed by default, read only, so **no lock, no Tesoreria, no sequences, no write port, no
G1..G5 gate** (the custody FLAG `G-CUS` guards custody MOVEMENTS; this class only READS the custody calculation, so `Compuertas(listas, false, false, false, false, false)` must be enough).
If production needs another shape, change the tests (not the golden): nothing of the comparison depends on these names except the entry points marked (*).

**What CPF really is** (cards FM-CPF-01..14, defects D-F3A-03..08 and D-F3A-27): four SQL of its own (`ConsultarCustodiaPortafolioFondoMutuo_SelectSolicitudes / _SelectSolicitudesTotales /
_SelectSeries / _SelectRegimen.sql`, already in `src/main/resources/cl/bcs/fondomutuo/sql/`, verbatim), FOUR valuations with `CalcularMontoNumeroCuota` (solicitudes, custody, guarantee,
rescate in transit), the custody calculation `ConsultarCustodiaPortafolioFFMM` (another piece), `ObtenerDiaSiguiente` and `ConsultarEmpresa` (always, D-F3A-07) and one
`CalcularParidad` (IdTrabajo 2). The oracle ran CPF, `CalcularMontoNumeroCuota` and `ObtenerDiaSiguiente` REAL; the four collaborators outside the module were scripted doubles.

## 2. Contract types (field names = legacy, JSON = legacy)

### 2.1 Entry and exit of the class
* `Entrada`: `Long p_IdEmpresa; Long p_IdUsuario; String p_IdModulo; Long p_IdCliente = 0; Long p_IdPortafolio = 0; Long p_IdInstrumento = 0; String p_FechaConsulta = "0001-01-01"; Long p_IdProductoAgrupador; String p_IdEmisor; String p_IdFamiliaFondo = ""; String p_BuscaMLT = "N"` IN THIS ORDER (defaults = the legacy constructor; an absent key keeps the default, an explicit JSON `null` overrides it with null; `"1"` is coerced by Gson to 1; `"abc"` and `1.5` raise `JsonSyntaxException`).
* `Salida`: ONLY `List<SalidaCustodia> P_OUT_TBL = []`. There is no error counter and no message list (D-F3A-27): the CallServlet decision is ROLLBACK for EVERY response (the counter is absent), so the harness records `decisionServlet = ROLLBACK`.
* `SalidaCustodia`: the 54 fields of the legacy class of the same name, in declaration order (`IdClasificacionTipoInstrumento ... MontoGarantia`), same Java types, with the legacy constructor defaults (`CantidadCustodia, Monto, ValorCuota, CantidadGarantia, CantidadTransSolicitudesAporte, CantidadTransSolicitudesRescate, INGPrecioPromedioCompra, INGMontoPrecioPromedioCompra, INGMontoPrecioPromedioMonedaInstrumento, PPPCustodia, MontoGarantiaMonedaSistema, MontoGarantia = 0`, `RegimenTributario = ""`, `RestringeRescate = "N"`; `MontoTransSolicitudesAporte` and `MontoTransSolicitudesRescate` have NO default: null). `CpfCompuertaTest.contratoDeLaFilaDeSalida` pins the full text of a default row.
* Numbers are written with their `BigDecimal.toString` (`0E-8`, `10.0000`, `15001`): the scale of every number is part of the golden.

### 2.2 Rows of the four SQL (inside `ConsultarCustodiaPortafolioDatos`, by column label)
`Solicitud` (the 22 columns of `SelectSolicitudes` plus `IdInterno`), `SolicitudTotal` (`IdInstrumento, IdPortafolio, Contador`), `SerieFondo` (19 columns of `SelectSeries`), `Regimen` (`IdSerieFondo, AceptaMandatoEnReinversion, RescateConMandato`); field names and Java types as the legacy classes of the same name.

### 2.3 Collaborators and what the oracle recorded of each call
Every call is part of the golden (name, arguments, answer), IN ORDER, with the arguments compared as canonical JSON (keys sorted, nulls kept):
1. `CalcularMontoNumeroCuota` valuation of the solicitudes (only the rows with `CantidadAporte > 0` / `CantidadRescate > 0`): `EntregarPreciosTasas` (`IdRegistro` = IdInterno, `IdUso` `CARTERA`, `GARANTIA` for `IdTipoMovimientoFondoMutuo = INGGTA`) and `CalcularParidad` (IdTrabajo 2: `IdInterno` = 4 id +- 1/2/3).
2. `ConsultarCustodiaPortafolioFFMM` (the custody port), ONCE, with `{p_IdEmpresa, p_IdUsuario, p_IdModulo, p_IdCliente, p_IdPortafolio, p_IdProductoAgrupador, p_IdEmisor, p_IdInstrumento, p_IdBoveda "", p_AgrupaPorBoveda "N", p_AgrupaPorRelacion "N", p_FechaConsulta (the REAL date), p_TipoFechaConsulta "LIQ", p_IdFamiliaFondo}` (nulls written).
3. The valuation of the custody (IdInterno 1..n of the saldos in HashMap order), then of the guarantee (IdInterno * -2) and of the rescate in transit (IdInterno * -1): each is a `CalcularMontoNumeroCuota` call that happens EVEN with no series (it reads its parameters) but then makes no collaborator call.
4. `ConsultarEmpresa` (kit `EmpresaPort`, argument the company id) ALWAYS (D-F3A-07: even with `PLA.CalculaValorCuotaDiaSiguiente` = 'N'), then `ObtenerDiaSiguiente` (in process, no call recorded), then ONE `CalcularParidad` (IdTrabajo 2, `IdInterno` 1..n, `IdMonedaOrigen` = fund currency, `IdMonedaDestino` = `PLA.MonedaSistema`, `MontoOrigen` = ValorCuota, `Fecha` = the next working day of `FechaValorCuota` when the parameter is exactly 'S', else the date of the query).

### 2.4 JSON contract of the custody port (NEW)
Entry `CustodiaEntrada` (14 fields as in 2.3 item 2, legacy order `p_IdEmpresa, p_IdUsuario, p_IdModulo, p_IdCliente, p_IdPortafolio, p_IdProductoAgrupador, p_IdEmisor, p_IdInstrumento, p_IdBoveda, p_AgrupaPorBoveda, p_AgrupaPorRelacion, p_FechaConsulta, p_TipoFechaConsulta, p_IdFamiliaFondo`, serialised with nulls) and exit `{"p_out_tbl": [CustodiaFila]}` with `CustodiaFila` = the 29 fields of the legacy `ConsultarCustodiaPortafolioFFMM.SalidaCustodia` (`IdClasificacionTipoInstrumento ... PPPCustodia`). A response with `p_out_tbl` null is a `NullPointerException` when the class iterates it (kept).

## 3. Behaviour the tests pin (bug for bug; the golden is the oracle, this is the index)

* **Order of the steps (and of the exceptions):** `PLA.FechaSistema` is read FIRST (so an unknown / null company fails before anything else, even with an explicit date); then `WS_SOLICITUDES_MUESTRA_SOLO_SOLICITUDES_NO_AUTOMATICAS`; the solicitudes SQL; its valuation; the totals SQL; the custody; the saldos; `PLA.MonedaSistema`; the series SQL; the regimes SQL; the three valuations; `PLA.CalculaValorCuotaDiaSiguiente`; `ConsultarEmpresa` + `ObtenerDiaSiguiente`; `CalcularParidad`; `PLA.MonedaSistema` again; the output. All the parameters are MANDATORY: a missing one is `Exception("Parametro X en modulo Y no encontrado")` (message compared).
* **Date of the query** (FM-CPF-02): `"0001-01-01"` or null => `PLA.FechaSistema`; any other text is used as is (no validation: `""` and `"hoy"` fail in the valuation with `DateTimeParseException`).
* **Solicitudes in transit** (FM-CPF-03): states ING/PEN, types APO/RES, `CalculoPorMontoCuota != 'T'`, the filters, the automatic-income filter (exempts regimen BF), the Spot amount; `IdInterno` of the rows = 2, 3, ... (D-F3A-04). **The legacy assigns them inside `parallelStream().forEach`: which row gets which id is the JDK's splitting order (2 rows: 3,2; 3 rows: 4,3,2; 4 rows: 5,4,2,3, the same with 0, 1 and 2 worker threads), not a rule: the tests compare the ids of the FIRST valuation modulo renaming (the SET must be exactly 2..n+1 and they are renamed by order of first appearance, `CpfEquivalenciaTest.conIdsCanonicos`). Any assignment of 2..n+1 passes; the production code may use plain row order.**
* **Valuation of the solicitudes** (FM-CPF-04, D-F3A-05): one `Serie` per row with cuotas > 0 (aportes first, then rescates, ids `IdInterno * 1` / `* -1`), results into a `Collectors.toMap` by `IdInterno` (a repeated or null key twice => `IllegalStateException`), `CantidadAporte := NumeroCuotas` and `CantidadMontoAporte := MontoMonedaSistemaAporte` when `CalculoPorMontoCuota = 'M'` else the valued `MontoMonedaSistema`; rescate always `MontoMonedaSistema`.
* **Saldos** (FM-CPF-05/07/09): a `java.util.HashMap<String,..>` keyed `IdCliente_IdPortafolio_IdInstrumento_IdRegimenFondoMutuo` filled solicitudes FIRST (a second row only adds the four quantities, `MathContext.DECIMAL128`, `new.add(old)`) then custody (the LAST one of a key wins); the output order is the iteration order of THAT map (D-F3A-04: stable for the same keys, resizes at 13 entries) and the internal `IdInterno` of the saldos is 1, 2, ... in that order for the saldos whose instrument has a series. **Use a `HashMap` with the default capacity and the same insertion order: any other map changes the order and `CpfEquivalenciaTest` reports it as an ORDER difference.**
* **Rest of the cards:** FM-CPF-08 (series by instrument with `ListaHash` => `Exception("key field is not unique")`; a saldo whose instrument has no series is omitted; `Nemotecnico = IdSerieFondo`, `NombreAdministradora = IdEmisor`: D-F3A-06), FM-CPF-10 (MLT by the FIRST regimen of the series: D-F3A-08), FM-CPF-11/12 (valuation of custody, guarantee asked with `IdInterno * -2` and looked up with `IdInterno`: `MontoGarantia` is ALWAYS 0, D-F3A-03; rescate in transit valued with type APO), FM-CPF-13 (`ValorCuotaMonedaSistema` = `MontoDestino` or 0; amounts formatted with `FormatoMoneda.formatear(.., MONTO, PLA.MonedaSistema)`; if the formatting raises, the unformatted product).
* **Exceptions:** class compared (the message only for a plain `Exception`: the missing parameters, `key field is not unique`, the scripted collaborator failures). KNOWN KIT DEVIATION **DESVIO-KIT-1** (decided by the owner: the kit's behaviour is KEPT): for `empresa-ausente`, `empresa-nula` and `empresa-sin-configuracion` the legacy raises `NullPointerException` and the kit `ParametroNoEncontradoException`; the harness accepts either for those three slugs ONLY (`CasoCpf.DESVIO_KIT_EMPRESA_SIN_CONFIGURACION`).
* Read only: the tables of the dump come back unchanged; no session-local table, no autonomous commit, no sequence.
