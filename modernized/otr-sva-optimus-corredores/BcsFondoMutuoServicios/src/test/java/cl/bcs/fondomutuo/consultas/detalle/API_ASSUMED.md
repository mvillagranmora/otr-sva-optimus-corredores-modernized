# API assumed by the FMM-DET tests (ConsultarDetalleSolicitud, F3 W1 front 4)

The production code does NOT exist yet. The tests of this package (`CasoDet`, `SujetoDet`, `DetEquivalenciaTest`, `DetDeterminismoTest`, `DetReglasTest`, `DetCompuertaTest`) are
written against EXACTLY the classes, constructors and methods below, all in package `cl.bcs.fondomutuo.consultas.detalle` (main source set) unless another package is named.
Legacy FQN: `cl.bcs.fondomutuo.ConsultarDetalleSolicitud` (the handler answers to it). Design = F1/F2/FSA style: service + read ports + JavaCall handler, closed by default, read
only, so **no lock, no Tesoreria, no custody, no sequences, no write port, no G1..G5 gate**. The two Plataforma collaborators of `CalcularMontoNumeroCuota` (`CalcularParidad`,
`EntregarPreciosTasas`) are READ-ONLY HTTP ports that already exist (`port.out.http.ParidadPort`, `PreciosTasasPort`). If production needs another shape, change the tests (not the golden):
nothing of the comparison depends on these names except the entry points marked (*).

**What DET really is** (card FM-DET-02, D-F3A-24): `ConsultarDetalleSolicitud` has no SQL of its own (`ConsultarDetalleSolicitud_SelectSolcitudes.sql` is on disk and no class loads
it). It delegates to the legacy `ConsultarSolicitudAporteRescateUI`, which runs `ConsultarSolicitudAporteRescateUI_SelectSolicitudes.sql` (270 lines), VALUES the solicitudes in state
`ING` / `PEN` with `CalcularMontoNumeroCuota` and computes the APV retention; DET then copies 110 fields. The oracle ran those THREE real classes, so this front pins the delegate's logic
too: the production DET service must contain it (the delegate is not a separate front: "documentar la delegada como unidad propia" stays open, Q in card FM-DET-02).

## 2. Contract types (field names = legacy, JSON = legacy)

* `Entrada`: `Long p_IdEmpresa; Long p_IdUsuario; String p_IdModulo; Long p_SolicitudesAporteRescate` (NO defaults: an absent key is `null`; a JSON text `"5"` is coerced by Gson to 5; `"abc"` and `1.5` raise `JsonSyntaxException`).
* `Salida`: `List<OutSolicitudesAporteRescate> P_OUT_RESULTADO = []; Long P_OUT_ERRORESCONTADOR = 0L; List<kit.MensajeSalida> P_OUT_MENSAJES = []` IN THIS FIELD ORDER (result first, unlike the other fronts).
* `OutSolicitudesAporteRescate`: the 110 fields of the legacy class of the same name, in declaration order (`IdSolicitudAporteRescate, IdCliente, IdPortafolio, FechaEmision (java.sql.Date), FechaIngresoRegistro (java.sql.Timestamp), IdTipoMovimientoFondoMutuo, ..., IdOperacionSpot, NombreEstadoSpot, ..., IdOmnibus, IdAgrupador`), same Java types; the golden has 93 written (nulls omitted).
* `SolicitudUi`: the 129 fields of the legacy `ConsultarSolicitudAporteRescateUI.Solicitud` (the row of the SQL, same names and Java types: `java.sql.Date` for the dates of the solicitud, `java.sql.Timestamp` for the `...Registro`, `BigDecimal` for the amounts, `String FechaLiquidacionTesoreria`); only some fields are copied to the output.
* JSON in and out: **a new `com.google.gson.Gson()` PER CALL** (the plain Gson of the legacy; NOT the static `JsonLegacy.plano()`): `java.sql.Date` is written as `MMM d, yyyy` (the year-1 default date as `Jan 3, 0001`), `java.sql.Timestamp` as `MMM d, yyyy, h:mm:ss a` with the JDK 20+ narrow no-break space U+202F, both in the zone of the JVM when the Gson is CREATED (a cached instance would freeze it; the goldens were recorded with the zone UTC and language en). Nulls not written; `BigDecimal` with its `toString` (`0E-8`).

## 3. Behaviour the tests pin (bug for bug; the golden is the oracle, this is the index)

* **Validation** (FM-DET-01): `p_SolicitudesAporteRescate` null or 0 => counter 1, message `NO_SE_INGRESARON_SOLICITUDES_APORTE_RESCATE` (id 0, type `ERROR`, dictionary text or `<codigo> sin traduccion`, built with `p_IdEmpresa` even when null), empty result, nothing else read (not even the parameters of the valuation); no `RevisarRequisitosBasicos`, no profile.
* **Delegate query** (FM-DET-02): the SQL above for the company and the id; a negative or unknown id, or another company, gives an empty list (counter 0, no message).
* **Valuation** (FM-DET-02, D-F3A-24): ALWAYS runs `CalcularMontoNumeroCuota` (it reads `FONDOMUTUO/UsaDolarObservado` and `PLATAFORMA/PLA.MonedaSistema`, and `ConfiguracionSistema` fails with `NullPointerException` for a null / unknown company even with no series), with one `Serie` per solicitud whose `EstadoSolicitud` is exactly `ING` or `PEN` (`IdInterno` = solicitud id, `Fecha` = `FechaValorCuota` as `yyyy-MM-dd`, `TipoFactorAjuste` `UF`, `IdTipoMovimientoFondoMutuo` null => `""`). The results go into a `Collectors.toMap` by `IdInterno` (a repeated id => `IllegalStateException`: a solicitud repeated by the JOIN; the message text is order dependent, only the class is compared) and every solicitud WITH a result (even an `ERROR_VALORCUOTA` one with null fields) gets `CostoMonedaLocal, Monto, ValorCuota, NumeroCuotas, ParidadFechaCertificacion, CostoUF, ValorUFFechaInversion` overwritten and `MontoMonedaSistema` only when the type is `RES`, or `APO` with `IdOperacionSpot` null or 0 (all of them are copied to the DET output). The collaborator calls (name, arguments, answer) are part of the golden: `EntregarPreciosTasas` once (country 56, `IdRegistro` = the id, `FechaConsulta` = the value date at 00:00:00.000, `IdUso` `CARTERA`) and `CalcularParidad` with `IdTrabajo` 2 (`IdInterno` = id*4+1 / +2 / +3), plus `IdTrabajo` 1 for a different currency; with no series NEITHER is called.
* **Retention** (FM-DET-03): after the valuation, for each solicitud with `IdTipoMovimientoFondoMutuo` = `RESNORM` (exact), `IdRegimenTributarioAPV` in (`APV-AN`, `APV-B`) (the SQL derives it from the portfolio purpose), `IdTraspaso == null` and `IdMedioDePago != "CIN"`: `MontoRetencion = Monto * (APV.PorcentajeRetencion / 100)` with `DECIMAL128`, then `FormatoMoneda.formatear(MONTO, IdMoneda)`; if the formatting raises, the unformatted value. `APV.PorcentajeRetencion` is read with `ConfiguracionSistemaPort.entero` inside a try/catch (missing, `12.5` or `abc` => 0); `Monto == null` (a failed valuation) => `NullPointerException`, not caught.
* **Mapping** (FM-DET-04): every field of the output is copied from the row of the same name, in the order of the SQL result; a row repeated by a JOIN (two Spot operations, two transfer orders) is repeated in the output.
* **Exceptions**: class compared (the message only for a plain `Exception`: the missing parameters). KNOWN KIT DEVIATION **DESVIO-KIT-1** (same as SFM): for `empresa-nula-con-id` and `empresa-sin-configuracion` the legacy raises `NullPointerException` and the kit `ParametroNoEncontradoException`; the harness accepts either for those two slugs ONLY (`CasoDet.DESVIO_KIT_EMPRESA_SIN_CONFIGURACION`).
* Read only: the tables of the dump come back unchanged; no session-local table, no autonomous commit, no sequence.
