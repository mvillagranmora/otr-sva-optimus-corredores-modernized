# centralizagz: WP-F characterization tests

These tests cover the legacy centralization types `CentralizaInteresReajusteCarteraTerminoRFIF` through
`CentralizaVentaTerminoSpread`, plus the gaps that `CentralizacionOrchestratorTest` leaves against
`CentralizaMultiSeleccion`. The **legacy source is the oracle**:
`legacy/otr-sva-optimus-corredores/BSCL/Contabilidad/JAVA/BcsContabilidadServicios/src/cl/bcs/contabilidad/`.
When a test fails, the modern code differs from the legacy code. Do not change the expectation to make it pass.

Behaviour ids are `CONT-F-001` to `CONT-F-251`. Each one appears in the test's `@DisplayName` and method name
(`contF042_...`), and a comment above each test gives the legacy file and line(s) it pins.

## Layout

| File | Role |
|---|---|
| `Fx.java` | Fixture constants. All synthetic values; the broker RUT `76999999-9` is fake. |
| `Spec.java` | Declarative transcription of one legacy type: SQL files, named params, TabDatosMovimiento fields and formats. |
| `Escenario.java` | Mocked `PlataformaPort` and `ContabilidadRepository`. It records every `queryDatosMovimientoRows(sqlFile, params)` call and answers it with rows registered per legacy SQL file name. Configuration parameters are answered only for the exact `MODULO|PARAMETRO` key the legacy reads. The AnticipoPactos-specific port methods return a SENTINEL row. |
| `Filas.java` | Deterministic fixture rows (legacy POJO column names) and the expected output computed from the legacy formatting rules. |
| `Casos.java` | The shared checks used by every type. |
| `Centraliza*CharacterizationTest.java` | One class per legacy type, generated by `src/test/resources/centralizagz/generator/gen.py` (specs in `specs.py`; run `python gen.py <this dir>`). Hand-written special cases (paridad, locks, historic queries) are at the end of each class. |
| `CentralizacionOrchestratorGapsCharacterizationTest.java` | Gaps against `CentralizaMultiSeleccion`. |

## Running

```bash
export JAVA_HOME="/c/Program Files/Eclipse Adoptium/jdk-25.0.4.101-hotspot"; export PATH="$JAVA_HOME/bin:$PATH"
mvn -o -f modernized/otr-sva-optimus-corredores/BcsContabilidadServicios/pom.xml test \
    -Dtest='cl.bcs.contabilidad.centralizagz.*Test' --batch-mode
```

Nothing in this package is skipped or `@Disabled`. If a SQL resource or a query is missing, the test fails.

## Adding a case

1. Read the legacy class. Note every `params.put`, every `sql.query(...)` file, and every
   `out.P_TABDATOSMOVIMIENTO.add(...)` line in order.
2. Pick the `Spec.Formato` for each field:
   - `mov.X` (String) is `STR`.
   - `String.valueOf(mov.X)` is `VALUEOF_LONG` or `VALUEOF_STR`.
   - `Fecha.stringToSqlDate` is `DATE`.
   - `mov.X.toString()` is `TOSTRING_DATE` or `TOSTRING_STR`.
   - A literal `""` is `CONST`.
   - `"" , mov.X` (a decimal value) is `DECIMAL`.
   - `Fecha.toStringTimeStamp` with the `0001-01-01 00:00:00` default is `TS_O_DEFECTO`.
   - `Fecha.toStringDatetime` is `DATETIME`.
3. Add or modify the `Spec.Tipo` in the class, or add a hand-written `@Test` with the next free `CONT-F-NNN`
   id and a `// Legacy File.java:line` comment.
