- Whole path: legacy JSON, registry lookup, `MapeoOperacion.entradaDesdeJson`, REAL use case on the given H2 `jdbc`, `resultadoAJson`, legacy JSON compared with the golden. In process, no HTTP.
- Ports are the SAME as BcsTesoreriaServicios, copied to `cl.bcs.apv.domain.port.out`: `Colaboradores` (`JsonObject invocar(String, JsonObject)`), `DiccionarioMensajes`, `ConfiguracionSistema`, `Secuencias`, `Reloj`, `AlmacenArchivos` (+ the `NamedParameterJdbcTemplate`). Services take them in the order `jdbc, configuracion, diccionario, secuencias, reloj, archivos, colaboradores` (`ApvCasosDeUso.crear`).
- Runtime exceptions of a use case propagate through the pipeline unchanged (legacy "NPE as behavior"); a Step 1 case that pins an exception asserts it on `invocar`.
- `ValidarBancoPrevired` and `ValidarMandatosPAC` answer `null` from `invocar` (their legacy `call()` returns null).
- Use cases are plain classes (no `@Service` yet; REST is not wired): the factory builds them.

## 5. Mapping rules the adapter applies (implemented in `MapeoJson` and the generated mappers)

- **Key missing** in the legacy JSON: the component takes the legacy default, i.e. the value the legacy constructor/field initialiser gave (`X.porDefecto()`: empty `ArrayList`, `0L`, `""`, `BigDecimal.ZERO`, `new Nested()`); with no initialiser: `null` (objects), `0`/`false` (Java primitives, 82 fields).
- **Key present with JSON null**: `null` (Gson assigns null over the constructor default, lists included: `{"p_Parametros":null}` gives a null list); for a Java primitive component the default stays (Gson does not assign null to a primitive).
- **Unknown keys** are ignored (Gson). Key matching is case sensitive and uses the legacy field names (`p_IdEmpresa`, `IdContrato`, `P_OUT_MENSAJES`...), which exist only in the mappers and in the annex.
- **Typed names**: legacy name without `p_`/`P_OUT_`/`P_` prefix, first letter lower case (`p_IdEmpresa` is `idEmpresa`, `P_OUT_MENSAJES` is `mensajes`, `P_OUT_ERRORESCONTADOR` is `contadorErrores`, `IdContratoSAAPV` is `idContratoSAAPV`). Collisions get a suffix (only `SalidaRevocacionContrato`: `contadorErrores` vs `contadorErroresLegacy`). Java keywords get `Valor`.
- **Scalars** are converted by the same Gson instance the legacy used (`Sabor`), reading the TEXT of each element as the legacy did with `in.toString()`: `"12"` to Long 12, number to String, `1.5` to Long fails with `JsonSyntaxException`, `BigDecimal` keeps the literal scale (`100.50` stays scale 2; verified in `ApvJavaCallRegistroTest`). Records use `Long`, `Integer`, `Double`, `Boolean`, `String`, `BigDecimal` exactly as the legacy POJO; legacy Java primitives (`long`, `double`) stay primitives.
- **Lists** (`List<X>`, `ArrayList<X>`, arrays): JSON array; null elements are kept as null elements; a non-array is a `JsonSyntaxException`. Nested POJOs become records in the same operation package; two legacy classes of the same name in one operation get the parent name as prefix.
- **Dates**: only 5 reachable fields (`ConsultarClienteContratoSAAPV.ContratoSAAPV`, `java.sql.Date`): typed `LocalDate`; read/written with the SAME Gson date adapter (plain `new Gson()` writes `"MMM d, yyyy"`, US locale). `java.util.Date` would be `LocalDateTime` in the system zone. The other legacy dates travel as `String` (the POJOs declare them as String) and are not touched.
- **Output**: with `plain` Gson null members are OMITTED (e.g. `P_OUT_ERRORESCONTADOR` is absent when the legacy never set it); with `builder` they are written as JSON null; null array elements are always written. Member order follows Gson (declared fields of the class, then of the superclass).
- **Messages** (`MensajeSalida`): `Mensaje(id, tipo, codigo, descripcion)` with the same flavour of the operation.
- **Opaque payloads**: 10 fields typed with Tesoreria POJOs (`CrearIngresoEgreso.IngresoEgreso_Entrada`, `FormaDePago_Entrada`, `CrearComprobante.*`) are carried as `JsonObject`/`List<JsonObject>`, untouched.
- **Envelope**: the legacy output is exactly the Salida object (`P_OUT_MENSAJES`, `P_OUT_ERRORESCONTADOR` and the operation specific fields); no extra wrapper is added by the adapter.

## 7. Open questions for a human

- **Route and use case naming** (all proposals in `tools/catalogo.py`, one edit and a re-run changes code and docs): Spanish plural for batch operations (`GrabarContratos`), `/apv/contratos`, `/apv/traspasos/anulacion`, `/apv/recaudaciones/...`, `/apv/bonificaciones/...`, `/apv/pac/...`; family C mixes recaudacion, bonificacion, PAC and Previred banks: split in two modules/packages?
